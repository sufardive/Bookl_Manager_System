# 图书管理系统开发路线图

> 项目类型：C# WinForms 桌面应用
> 当前阶段：基础图书管理与 TCP 通信已完成第一轮拆分
> 下一阶段：SQLite 数据持久化

## 1. 项目目标

把当前的练习项目逐步发展成一个功能完整、结构清晰、可以持续扩展的图书管理系统。

项目不以「堆技术」为目标，而是围绕真实需求逐步增加功能。每引入一种技术，都应该能回答一个问题：

- 为什么需要它？
- 它解决了什么问题？
- 它应该放在哪一层？
- 如何验证它确实有效？

## 3. 当前需要留意的技术问题

这些问题不必全部同时解决，可以在相应阶段处理。

- [ ] 添加图书时，对价格输入使用 `double.TryParse`，避免非法输入导致异常。
- [ ] 查询图书时，检查查询结果是否为 `null`，再绑定到表格。
- [ ] 修改图书时，通过当前行绑定的 `Books` 对象取得真实 `bookId`，不要把行下标当作图书 ID。
- [ ] TCP 接收端不能假设一次 `ReadAsync` 就对应一条完整消息。后续需要明确消息边界，处理 TCP 拆包和粘包。
- [ ] 窗体关闭时，确保 TCP 后台任务被取消并等待结束。
- [ ] 后续可为 `BookService` 的集合访问增加合适的封装，避免外部随意修改内部集合。

## 4. 开发阶段规划

### 阶段一：基础图书管理与 TCP 通信

**状态：第一轮基本完成**

目标：

- 完成图书 CRUD。
- 将图书业务放入 `BookService`。
- 将 TCP 通信放入 `TcpClientService`。
- 通过 `BookReceived` 事件把接收到的图书信息通知 `Form1`。
- 由 `Form1` 在 UI 线程更新界面。

完成标准：

- 手动添加、删除、修改、查询图书正常。
- TCP 能启动、接收数据并停止。
- TCP 收到图书数据后，界面能够显示新图书。

### 阶段二：SQLite 数据持久化

**状态：下一阶段**

#### 为什么先做数据库？

当前图书保存在 `List<Books>` 中。程序关闭后，内存中的数据会消失。

引入数据库后，图书数据可以保存在磁盘上，程序重新启动仍然能够读取。

#### 技术选择

第一版建议使用 SQLite：

- 不需要单独部署数据库服务器。
- 数据通常保存在一个 `.db` 文件中。
- 适合当前单机 WinForms 项目。
- 可以练习关系型数据库和 SQL 基础。

具体 NuGet 包和连接方式，需要先确认项目的目标框架，再决定使用哪一种 SQLite 提供程序。

#### 学习与开发顺序

1. 确认项目目标框架和 C# 语言版本。
2. 安装合适的 SQLite NuGet 包。
3. 创建数据库文件。
4. 创建 `Books` 数据表。
5. 学习主键、字段、约束和基本 SQL。
6. 实现新增：`INSERT`。
7. 实现查询：`SELECT`。
8. 实现修改：`UPDATE`。
9. 实现删除：`DELETE`。
10. 程序启动时从数据库加载图书。
11. 将 TCP 收到的新图书也保存到数据库。

#### 预期架构

```text
Form1
  |
  v
BookService
  |
  v
BookRepository
  |
  v
SQLite
```

职责：

| 部分 | 职责 |
| --- | --- |
| `Form1` | 用户交互和界面展示 |
| `BookService` | 图书业务规则 |
| `BookRepository` | 数据库读写 |
| SQLite | 持久化保存数据 |

#### 完成标准

- [ ] 首次启动时能够创建或初始化数据库。
- [ ] 添加图书后，数据库中有对应记录。
- [ ] 修改和删除图书会同步更新数据库。
- [ ] 查询功能从持久化数据中取得结果。
- [ ] 关闭程序再重新打开，图书数据仍然存在。
- [ ] TCP 接收的新图书也能够保存到数据库。

### 阶段三：库存与借阅管理

**前置条件：阶段二的数据持久化已经稳定。**

建议增加的数据概念：

- 图书库存
- 可借数量
- 借阅人
- 借阅记录
- 借出时间
- 应还时间
- 实际归还时间

建议开发顺序：

1. 设计库存字段或库存记录。
2. 设计借阅记录表。
3. 实现借阅操作。
4. 借阅成功后减少可借数量。
5. 实现归还操作。
6. 归还成功后恢复可借数量。
7. 增加逾期判断。
8. 查询某本书的借阅历史。

需要注意：借阅记录和库存变化应保持一致。数据库事务会在这一阶段变得重要。

### 阶段四：ISBN 扫码与图书信息自动录入

目标：减少人工录入图书信息的工作量。

建议分成三个小阶段：

1. **扫码输入**：先使用 USB 扫码枪。许多扫码枪会模拟键盘输入，把 ISBN 写入文本框，并发送回车键。
2. **ISBN 查询**：根据 ISBN 调用图书信息 API，尝试取得书名、作者、出版社、封面等资料。
3. **确认入库**：把查询结果填入界面，由用户确认后保存。

注意：条码通常提供的是 ISBN 编号，不一定直接包含完整的书名、作者等资料；完整资料需要通过图书信息数据源查询。

### 阶段五：用户与权限管理

可增加：

- 用户登录
- 管理员和普通用户角色
- 不同角色的操作权限
- 用户借阅记录
- 操作日志

这部分可以练习身份认证、授权和用户数据管理。

### 阶段六：网络化与多客户端

当单机版本稳定后，再考虑让多台电脑共享同一套图书数据。

可以逐步引入：

- ASP.NET Core Web API
- HTTP / REST API
- WebSocket 实时通知
- 服务端与客户端分离
- 多客户端访问同一数据库

此时可以把现有 WinForms 保留为桌面客户端，再增加 Web 客户端。

### 阶段七：并发、可靠性与测试

当系统支持多个用户同时操作时，再针对真实问题学习：

| 场景 | 可学习的技术 |
| --- | --- |
| 两个人同时借最后一本书 | 数据库事务、并发控制 |
| 多个请求同时修改库存 | 乐观锁、悲观锁 |
| 大量用户同时查询 | 性能测试、索引、缓存 |
| 后台任务积压 | 队列、限流 |
| 程序出现异常 | 日志、异常处理、监控 |
| 修改代码后担心破坏旧功能 | 单元测试、集成测试 |

不需要一开始就引入 Redis、消息队列或微服务。先遇到实际需求，再选择对应技术。

### 阶段八：计算机视觉（可选扩展）

视觉功能可以作为独立扩展，不必阻塞核心图书管理功能。

可选方向：

- ISBN 条码图像识别
- OCR 识别书名、作者和出版社
- 书架图书检测与定位
- 图书封面相似度检索

建议先从条码识别或 OCR 入手，再考虑目标检测等更复杂的视觉任务。

## 6. 开发原则

1. **先完成可运行的功能，再扩展架构。** 不为了「看起来专业」而提前引入复杂设计。
2. **先理解问题，再选择技术。** 例如，数据丢失引出数据库，库存超卖引出事务和并发控制。
3. **每次只增加一个主要能力。** 完成后运行测试，再进入下一步。
4. **保留可工作的版本。** 大规模重构前先备份或使用 Git 提交。
5. **区分 UI、业务和数据访问。** `Form1` 不直接承担数据库读写，`BookService` 不直接操作 WinForms 控件。
6. **不要把所有技术都塞进项目。** 只有在业务需求合理时才引入新技术。
